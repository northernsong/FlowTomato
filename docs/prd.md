# FlowTomato 产品需求文档 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | FlowTomato |
| 产品定位 | 面向个人工作流的待办 + 番茄钟效率工具 |
| 当前版本 | MVP v0.1 |
| 来源文档 | `docs/brd.md` |
| 编写日期 | 2026-06-01 |
| 目标平台 | Web PWA，后续打包为 macOS App |

## 2. 背景与目标

### 2.1 背景

个人任务管理工具和番茄钟工具通常分离使用，用户需要在待办列表、计时器、统计工具之间频繁切换。FlowTomato 希望把“今天要做什么”“现在正在做什么”“已经完成了什么”“每项任务投入了多少番茄钟”放在同一个轻量界面中，并通过飞书多维表格作为可编辑、可同步的数据源。

### 2.2 产品目标

1. 帮助用户快速确定当前最重要的任务，并开始一次专注。
2. 让今日待办、当前任务、完成记录在同一界面内闭环。
3. 将任务和番茄钟记录沉淀到飞书多维表格，方便跨设备查看和二次统计。
4. 以高质量 UI 先验证核心体验，再逐步增强同步、统计和桌面端能力。

### 2.3 成功指标

| 指标 | MVP 目标 |
| --- | --- |
| 任务创建耗时 | 用户可在 5 秒内创建一条今日待办 |
| 开始专注路径 | 从任务列表到开始番茄钟不超过 2 次点击 |
| 今日闭环完整度 | 用户可在首页看到 Now、Todo、Done 三类信息 |
| 本地可用性 | 无飞书配置时也能完整使用本地假数据或本地存储 |
| 数据同步可观测性 | 接入飞书后，每条任务和番茄记录可判断同步成功或失败 |

## 3. 用户与使用场景

### 3.1 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人开发者 / 创作者 | 一天内有多个任务，需要深度工作 | 快速选中当前任务并进入专注状态 |
| 知识工作者 | 需要记录每日完成事项和投入时间 | 自动沉淀完成记录和番茄统计 |
| 飞书重度用户 | 已使用飞书多维表格做个人数据库 | 希望任务数据能同步到飞书 Base |

### 3.2 核心场景

1. 用户早上打开 FlowTomato，添加今日待办并按优先级排序。
2. 用户选择一条任务设为 Now，点击开始 25 分钟番茄钟。
3. 番茄钟结束后，系统提示休息，并记录该任务的一次专注。
4. 用户完成任务后，将其移动到 Done 区域。
5. 用户在一天结束时查看今日完成任务、番茄钟次数和总专注时长。
6. 接入飞书后，任务和番茄记录自动同步到多维表格。

## 4. 产品范围

### 4.1 MVP 范围

MVP 聚焦单人、今日任务、本地体验和漂亮 UI。

| 模块 | MVP 是否包含 | 说明 |
| --- | --- | --- |
| Now 当前任务 | 包含 | 显示当前任务卡片，支持开始番茄钟 |
| Todo 今日待办 | 包含 | 支持创建、编辑、完成、删除、优先级和排序 |
| Done 完成汇总 | 包含 | 显示今日完成任务、番茄次数、专注时长 |
| 番茄钟抽屉 | 包含 | 默认 25/5/15 分钟，支持开始、暂停、继续、重置 |
| 本地数据 | 包含 | 第一阶段使用假数据，后续可切换本地存储 |
| 飞书 Base 同步 | 第二阶段包含 | 读取、创建、更新任务；记录番茄钟 |
| 日统计 | 第三阶段包含 | 写入或计算 DailySummary |
| macOS App | 第四阶段包含 | 通过 PWA 或桌面封装方案实现 |

### 4.2 暂不包含

1. 多人协作、任务分配、评论。
2. 项目、标签、复杂看板视图。
3. AI 自动排期和智能任务拆分。
4. 跨账号权限管理。
5. 移动端原生 App。

## 5. 信息架构

主界面由三块任务区域和一个番茄钟抽屉组成。

```text
首页
├── 顶部栏
│   ├── 产品名称 / 日期
│   ├── 今日统计摘要
│   └── 设置入口
├── 主任务区
│   ├── Now 正在做
│   ├── Todo 待办
│   └── Done 完成汇总
└── Pomodoro 抽屉
    ├── 当前计时状态
    ├── 关联任务
    ├── 控制按钮
    └── 阶段切换
```

## 6. 页面与交互需求

### 6.1 首页布局

#### 功能说明

首页是产品的第一屏，也是 MVP 的唯一核心工作台。用户打开应用后，应直接看到今天正在处理的任务、待办列表、完成结果和番茄钟入口。

#### 布局要求

1. 主任务区按 Now、Todo、Done 三段纵向排列。
2. 番茄钟默认以右侧抽屉形式展示；窄屏下可改为底部面板或弹层。
3. 支持浅色和深色模式。
4. 视觉风格参考 Linear、Things 3、Raycast：极简、低饱和、卡片化、轻阴影、macOS 原生感。

#### 验收标准

1. 用户进入首页后无需跳转即可看到 Now、Todo、Done。
2. 当前任务和番茄钟状态在首屏有明显视觉焦点。
3. 页面在桌面宽屏和窄屏下均不出现内容重叠。

### 6.2 Now 正在做

#### 功能说明

Now 区域用于展示当前最重要的任务，并提供最快开始专注的入口。

#### 需求明细

| 编号 | 需求 |
| --- | --- |
| NOW-001 | 当存在当前任务时，显示任务标题、备注、优先级、预计番茄数、已完成番茄数 |
| NOW-002 | 当不存在当前任务时，显示空状态，引导用户从 Todo 中选择一项 |
| NOW-003 | 用户可点击“开始”按钮，为当前任务启动番茄钟 |
| NOW-004 | 用户可将当前任务标记为完成，任务进入 Done |
| NOW-005 | 用户可从当前任务退出 Now，任务回到 Todo |

#### 验收标准

1. 从 Todo 设置 Now 后，Now 区域立即更新。
2. 点击开始后，番茄钟自动关联当前任务。
3. 完成当前任务后，Done 区域出现该任务。

### 6.3 Todo 今日待办

#### 功能说明

Todo 区域承载当天计划完成的任务，是用户管理日内工作的主要入口。

#### 需求明细

| 编号 | 需求 |
| --- | --- |
| TODO-001 | 用户可创建任务，必填字段为任务标题 |
| TODO-002 | 用户可编辑任务标题、备注、优先级、预计番茄数 |
| TODO-003 | 用户可删除任务 |
| TODO-004 | 用户可将任务设为 Now |
| TODO-005 | 用户可将任务标记完成 |
| TODO-006 | 用户可按拖拽方式调整任务排序 |
| TODO-007 | 任务支持高、中、低三档优先级 |
| TODO-008 | 默认仅展示今日未完成任务 |

#### 验收标准

1. 新建任务后，任务出现在 Todo 列表中。
2. 编辑任务后，列表和 Now 中的同一任务信息保持一致。
3. 拖拽排序刷新后仍可保持。
4. 删除任务前需要二次确认或提供撤销入口。

### 6.4 Done 完成汇总

#### 功能说明

Done 区域帮助用户看到今日产出，形成正反馈。

#### 需求明细

| 编号 | 需求 |
| --- | --- |
| DONE-001 | 显示今日已完成任务列表 |
| DONE-002 | 显示今日完成任务数 |
| DONE-003 | 显示今日完成番茄钟次数 |
| DONE-004 | 显示今日累计专注时长 |
| DONE-005 | 用户可将已完成任务恢复到 Todo |

#### 验收标准

1. 任务完成后，统计数字实时变化。
2. 恢复任务后，Done 列表和统计数字同步回退。

### 6.5 Pomodoro 番茄钟

#### 功能说明

番茄钟用于记录专注、短休息和长休息周期，并与任务关联。

#### 默认规则

| 类型 | 默认时长 |
| --- | --- |
| 专注 | 25 分钟 |
| 短休息 | 5 分钟 |
| 长休息 | 15 分钟 |

#### 需求明细

| 编号 | 需求 |
| --- | --- |
| POMO-001 | 用户可开始、暂停、继续、重置计时 |
| POMO-002 | 专注计时可关联一个任务 |
| POMO-003 | 若没有当前任务，用户仍可启动无关联番茄钟 |
| POMO-004 | 专注结束后生成一条 Pomodoro 记录 |
| POMO-005 | 专注结束后触发系统通知 |
| POMO-006 | 用户可在专注、短休息、长休息之间切换 |
| POMO-007 | 支持自定义专注、短休息、长休息时长 |
| POMO-008 | 支持自动开始下一阶段的设置 |

#### 验收标准

1. 暂停后计时停止，继续后从剩余时间恢复。
2. 重置后回到当前阶段的初始时长。
3. 专注自然结束后，关联任务的已完成番茄数加 1。
4. 浏览器通知权限关闭时，应用内仍显示完成提示。

### 6.6 设置

#### 功能说明

设置用于管理番茄钟时长、通知偏好和飞书同步配置。

#### 需求明细

| 编号 | 需求 |
| --- | --- |
| SET-001 | 用户可设置专注、短休息、长休息时长 |
| SET-002 | 用户可开启或关闭系统通知 |
| SET-003 | 用户可开启或关闭自动开始下一阶段 |
| SET-004 | 用户可配置飞书 Base 凭据和表格信息 |
| SET-005 | 用户可测试飞书连接是否成功 |

#### 验收标准

1. 设置保存后刷新页面仍然生效。
2. 飞书连接测试失败时展示明确错误原因。

## 8. 飞书 Base 集成需求

### 8.1 集成目标

使用飞书多维表格 Base 作为任务和番茄记录的数据源，使 FlowTomato 的数据可在飞书中查看、编辑和备份。

### 8.2 集成范围

| 阶段 | 能力 |
| --- | --- |
| 第二阶段 | 读取 Tasks，创建 Tasks，更新 Tasks 状态和字段 |
| 第三阶段 | 写入 Pomodoro 记录，更新或生成 DailySummary |

### 8.3 同步规则

1. 应用启动时读取今日 Tasks。
2. 用户创建、编辑、完成、删除任务时，同步更新飞书记录。
3. 番茄钟自然结束时，写入一条 Pomodoro 记录。
4. 同步失败时，本地保留变更，并将记录标记为 failed。
5. 用户可手动重试同步失败的记录。

### 8.4 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 飞书未配置 | 使用本地数据，显示未同步状态 |
| Token 失效 | 提示重新配置或刷新凭据 |
| 网络失败 | 本地记录为 failed，允许重试 |
| 字段缺失 | 设置页提示 Base 表结构不完整 |
| 数据冲突 | MVP 以本地最新修改覆盖远端，后续再支持冲突合并 |

## 9. 非功能需求

### 9.1 性能

1. 首页首次可交互时间目标小于 2 秒。
2. 创建、编辑、完成任务的本地反馈应在 100ms 内完成。
3. 飞书同步不阻塞用户本地操作。

### 9.2 可用性

1. 无网络状态下，核心任务和番茄钟功能仍可使用。
2. 计时过程中刷新页面，应尽量恢复计时状态。
3. 系统通知不可用时，提供应用内提醒。

### 9.3 安全与隐私

1. 飞书凭据只存储在本地，不上传到第三方服务。
2. 设置页不明文展示完整敏感凭据。
3. 日志中不得输出完整 Token、Webhook 或 App Secret。

### 9.4 兼容性

1. 优先支持最新版 Chrome、Edge、Safari。
2. PWA 应支持安装到桌面。
3. macOS App 阶段需保持与 Web 版本一致的核心数据结构。

## 10. 视觉与体验要求

1. 整体风格：极简、卡片、毛玻璃、低饱和、macOS 原生感。
2. 信息层级：Now 最高，Todo 次之，Done 作为结果反馈。
3. 交互动效：轻量、克制，用于状态变化和抽屉展开收起。
4. 深浅色模式：颜色、阴影、边框均需适配。
5. 空状态：Now、Todo、Done 均需有简洁空状态。
6. 按钮与图标：常用操作使用清晰图标和短文本，避免冗长说明。

## 11. 版本规划

### 11.1 第一阶段：本地假数据 + 漂亮 UI

目标：验证核心界面和任务流。

范围：

1. 首页 Now、Todo、Done 三段布局。
2. 右侧 Pomodoro 抽屉静态或半动态展示。
3. 使用假数据呈现完整状态。
4. 支持基础交互：设为 Now、完成任务、开始计时。

交付标准：

1. 无需飞书配置即可展示完整应用体验。
2. UI 达到可演示水平。

### 11.2 第二阶段：接入飞书 Base API

目标：让任务数据从飞书读取并回写。

范围：

1. 配置飞书 Base 连接。
2. 读取今日 Tasks。
3. 创建、编辑、完成任务同步到飞书。
4. 展示同步状态。

交付标准：

1. 飞书 Tasks 表与应用内任务保持同步。
2. 同步失败时用户可感知并重试。

### 11.3 第三阶段：番茄钟 + 统计

目标：把专注记录沉淀为可统计数据。

范围：

1. 完整番茄钟状态机。
2. Pomodoro 记录写入飞书。
3. Done 区域展示今日统计。
4. DailySummary 生成或更新。

交付标准：

1. 每次完成专注后可追溯到任务和时间。
2. 今日统计与 Pomodoro 记录一致。

### 11.4 第四阶段：打包成 macOS App

目标：提供更接近原生应用的桌面体验。

范围：

1. 选择 PWA 安装或桌面封装方案。
2. 桌面通知适配。
3. 应用图标、启动体验、窗口尺寸适配。

交付标准：

1. 用户可在 macOS 桌面独立启动 FlowTomato。
2. 核心功能与 Web 版本一致。

## 12. 埋点与统计建议

| --- | --- | --- |

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 飞书 API 配置复杂 | 用户难以上手 | 第一阶段保证本地可用，第二阶段提供连接测试和字段校验 |
| 计时器刷新后状态丢失 | 影响专注体验 | 保存 startedAt、duration、pausedAt 等状态，刷新后恢复 |
| 数据同步冲突 | 任务状态不一致 | MVP 采用本地优先，后续补充冲突解决 |
| UI 过度设计影响效率 | 操作成本升高 | 保持首页工作台结构，核心操作不超过 2 次点击 |

## 14. 验收清单

### MVP 验收

1. 首页包含 Now、Todo、Done 和 Pomodoro 区域。
2. 用户可以创建、编辑、删除、排序、完成任务。
3. 用户可以将 Todo 任务设为 Now。
4. 用户可以启动、暂停、继续、重置番茄钟。
5. 专注结束后可以生成番茄记录并更新任务番茄数。
6. Done 区域可以展示今日完成任务数、番茄数和专注时长。
7. 设置可以保存番茄钟时长和通知偏好。
8. 无飞书配置时应用仍可使用。
9. 飞书接入后，任务和番茄记录具备同步状态。
10. 页面支持深浅色模式，并符合 macOS 风格方向。

## 15. 待确认问题

1. 飞书接入方式最终使用自建应用凭据、用户访问令牌，还是仅使用 Webhook。
2. Tasks、Pomodoro、DailySummary 三张表是否由应用自动创建，还是要求用户提前创建。
3. macOS App 阶段采用 PWA 安装、Electron、Tauri 还是其他封装方案。
4. 是否需要支持历史日期回看。
5. 是否需要在 MVP 中支持任务标签或项目分组。
